# Projects

A Rugix Bakery _project_ is a directory containing the following files and directories:

- `run-bakery`: Shell script for running Rugix Bakery pinned to a major version.
- `rugix-bakery.toml`: Project configuration file.
- `layers`: Directory containing project-specific layer configurations (optional).
- `recipes`: Directory containing project-specific recipes (optional).
- `rules`: Directory containing reusable [build rules](/docs/bakery/next/build-rules/) (optional).
- `envs`: Directory containing [tooling environments](/docs/bakery/next/envs) defined by Dockerfiles (optional).
- `tests`: Directory containing system tests (optional).

We also refer to the directory containing all these files and directories as the _project directory_.

Note that you must always run `./run-bakery` directly in the project directory.

## Project Templates

Templates provide a starting configuration and recipes for a project. You can
[browse the templates on GitHub](https://github.com/rugix/rugix-bakery/tree/main/container/templates)
or list those included in your Rugix Bakery version:

```shell
./run-bakery init
```

To initialize a new project, pass a template name. For example, in a directory
containing the `run-bakery` launcher and no `rugix-bakery.toml`:

```shell
./run-bakery init debian-grub-efi
```

Rugix Bakery includes these general-purpose templates:

| Template | Description |
| --- | --- |
| [`quickstart-guide`](https://github.com/rugix/rugix-bakery/tree/main/container/templates/quickstart-guide) | Debian for AMD64 and ARM64 EFI systems and Raspberry Pi 4 and 5, used in the [quickstart guide](/docs/getting-started/). |
| [`alpine-grub-efi`](https://github.com/rugix/rugix-bakery/tree/main/container/templates/alpine-grub-efi) | Alpine for AMD64 and ARM64 EFI systems, using GRUB. |
| [`debian-grub-efi`](https://github.com/rugix/rugix-bakery/tree/main/container/templates/debian-grub-efi) | Debian for AMD64 and ARM64 EFI systems, using GRUB. |
| [`yocto-grub-efi`](https://github.com/rugix/rugix-bakery/tree/main/container/templates/yocto-grub-efi) | Yocto for AMD64 and ARM64 QEMU systems, using GRUB. |
| [`rpi-alpine`](https://github.com/rugix/rugix-bakery/tree/main/container/templates/rpi-alpine) | Alpine for Raspberry Pi 4, Compute Module 4, and Pi 5. |
| [`rpi-debian`](https://github.com/rugix/rugix-bakery/tree/main/container/templates/rpi-debian) | Debian for Raspberry Pi 4, Compute Module 4, and Pi 5. |
| [`rpi-raspios`](https://github.com/rugix/rugix-bakery/tree/main/container/templates/rpi-raspios) | Raspberry Pi OS for all Raspberry Pi models. |

### Secure Boot

These Debian templates support signed boot and verified root filesystems.
Follow the linked READMEs for build and firmware setup instructions.

| Template | Hardware |
| --- | --- |
| [`debian-secure-efi`](https://github.com/rugix/rugix-bakery/tree/main/container/templates/debian-secure-efi) | AMD64 EFI; adaptable to ARM64 EFI |
| [`rpi-debian-secure`](https://github.com/rugix/rugix-bakery/tree/main/container/templates/rpi-debian-secure) | Raspberry Pi 4, Compute Module 4, and Pi 5 |

:::warning
Signed images provide no boot protection unless the firmware trusts your key
and enforces signatures. These templates do not encrypt or authenticate the
data partition; configure those protections separately.
:::

## Project Configuration

Each project is configured in a `rugix-bakery.toml` configuration file.
Such a file typically has two sections, `repositories` and `systems`.
We explain those sections in further detail in dedicated sections of this documentation.

To give you an idea how a configuration file may look like, here is an example:

```toml title="rugix-bakery.toml"
#:schema https://raw.githubusercontent.com/rugix/rugix/refs/tags/v0.8.0/schemas/rugix-bakery-project.schema.json

[repositories]
rugix-extra = { git = "https://github.com/rugix/rugix-extra.git", branch = "v0.9" }

[systems.customized-arm64]
layer = "customized"
architecture = "arm64"
```

The `#:schema` directive is used to specify a [JSON Schema](https://json-schema.org/) for the TOML file. Rugix Bakery comes with JSON Schemas for all its configuration files, enabling straightforward validation and autocompletion in modern IDEs.

## System Artifacts

A system's `rules` table instantiates reusable build rules. Its `outputs`
table maps published file names to graph artifacts. A `target` or `image`
also enables the predefined pipeline, whose outputs rules can use through the
reserved node `target`.
See [Systems](/docs/bakery/next/systems) for examples and bundle configuration.

```shell
./run-bakery bake system customized
./run-bakery bake system customized --artifact system.img --output build/image-only
```
